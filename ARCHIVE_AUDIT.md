# What changed and why

The supplied ZIP is an earlier implementation of the same research idea. Its SHA-256 is `87b1439caf8b1e1342a9d4aed230e35c8750debc9e0865ddd40b598ec861fa1b`. The original download remains the source of record. All seven CSVs distributed here were generated by the corrected engine.

| Question | What the supplied code actually does | Correction and evidence |
|---|---|---|
| Does P4 implement the 2011 comparison? | In `src/protocols/afek2011.py`, `_schedule_p` repeats a clamped sawtooth and `update` clears the winner's adjacent entries directly. A receiver can appear covered without hearing an announcement. | Finite Table 1 phase loop, two separate exchanges, last-decision and exhaustion measurements. The missed-announcement fixture leaves the receiver undecided. |
| Can a beep identify a sender? | The old EcoBeep `_split_heard` reads the flags of identified neighbors. Further code reads adjacency while updating other nodes. | Only the channel sees graph edges. Decision paths receive a Boolean. Contention, confirmation and final announcement have distinct slots. Exported observer IDs never feed decisions. |
| Does LEACH rotate heads consistently? | The old `reset_round` admits elections only on epoch boundaries. Lifetime runs construct fresh protocol instances. P2 divides by the observed maximum battery. | Eligibility persists through all 20 clustering rounds. P2 divides by configured rated energy. Tests include ineligibility, headless starts and the final-round threshold. |
| Is listening on silence charged? | In old `src/energy.py:charge_round`, the RX increment depends on receiving a packet. A sender also pays an extra TX debit on top of its baseline. | A node occupies exactly one mode at a time. A silent 40 ms listen costs 13.2 mJ and a 5 ms beep followed by 35 ms idle costs 6.27 mJ. |
| What do lifetime and service mean? | Archived E5 uses global rounds and a workload indexed to clustering. Maintenance and confirmation were disabled in that arm. It omits delivered source-report totals. | All arms share one clock, sink, MAC and offered workload. Death, repair, setup drops and delivered aggregates count in elapsed seconds. E5 includes the published adaptive reference and the otherwise-identical bias-off twin. |
| What does a passing test establish? | Existing gates include expected ranges of speed and failure rates. Archived E3 matches expected counts to the greedy oracle. | Tests use fixtures or identities. E3 takes the count from the paired P5 output and includes exact and expected controls. Outcome signs do not determine whether a run passes. |

The paper-based baseline, clocks, service rules and estimands changed together. An old number cannot be converted to a new result by renaming its units. Independent reproduction in this edition refers to rerunning the corrected implementation from clean output directories. The archived pipeline itself was source-reviewed; its historical runs were not independently reproduced.

The Windows edition uses a shared JavaScript engine for batch and browser simulation, with Python orchestration, independent reference fixtures, statistics and plotting. The experimental matrix and sample sizes are named in DECISIONS.md. This is a new frozen configuration, not a claim to have recreated historical container output.
